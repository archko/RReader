### 核心数据流

```
用户操作 → 手势处理 → offset/zoom变化 → updateOffset()
    → updateVisiblePages() 计算可见页面列表
    → Page.updateVisibleNodes() 按需创建/释放PageNode
    → PageNode.decode() 提交解码任务到DecodeService
    → DecodeService调度 → DecoderAdapter解码 → ImageBitmap返回
    → bitmapState更新 → Compose重组 → Canvas重绘
```

### 关键设计原则

1. **分层解码**: 缩略图(Page级) → 瓦片(PageNode级)，优先显示缩略图保证快速响应，再逐步用高清瓦片替换
2. **按需渲染**: 仅创建可见区域+预加载区域内的PageNode，超出范围立即回收
3. **对象池**: PageNode使用对象池(PageNodePool)避免高频GC
4. **三级缓存**: LRU内存缓存 + 60秒候选池(二次存活机会) + 引用计数
5. **优先级解码**: PAGE(缩略图) > NODE(瓦片) > CROP(裁剪检测)

## 3. 布局计算 (invalidatePageSizes)

### 3.1 触发条件

- `updateViewSize()` 被调用（viewSize/zoom/orientation变化时）
- `updateColumnCount()` 列数变化
- `setCropEnabled()` 切边状态变化
- 缩略图加载后检测到宽高比变化（`setAspectRatio`）

### 3.2 单列垂直模式 (columnCount=1, orientation=Vertical)

```
for each (aPage, page) in list.zip(pages):
    pageScale = scaledPageWidth / aPage.getWidth(useCrop)
    scaledPageWidth = viewSize.width * vZoom
    scaledPageHeight = aPage.getHeight(useCrop) * pageScale
    
    bounds = Rect(0, currentY, scaledPageWidth, currentY + scaledPageHeight)
    page.update(scaledPageWidth, scaledPageHeight, bounds)
    currentY += scaledPageHeight

totalHeight = currentY
totalWidth = viewSize.width * vZoom
```

### 3.3 单列水平模式 (columnCount=1, orientation=Horizontal)

```
for each (aPage, page) in list.zip(pages):
    pageScale = scaledPageHeight / aPage.getHeight(useCrop)
    scaledPageHeight = viewSize.height * vZoom
    scaledPageWidth = aPage.getWidth(useCrop) * pageScale
    
    bounds = Rect(currentX, 0, currentX + scaledPageWidth, scaledPageHeight)
    page.update(scaledPageWidth, scaledPageHeight, bounds)
    currentX += scaledPageWidth

totalWidth = currentX
totalHeight = viewSize.height * vZoom
```

### 3.4 多列模式 (columnCount > 1)

```
scaledPageWidth = (viewSize.width * vZoom) / columnCount

for each row (i += columnCount):
    maxHeightInRow = 0
    for each col (0 until columnCount):
        pageScale = scaledPageWidth / aPage.getWidth(useCrop)
        scaledPageHeight = aPage.getHeight(useCrop) * pageScale
        currentX = col * scaledPageWidth
        bounds = Rect(currentX, currentY, currentX + scaledPageWidth, currentY + scaledPageHeight)
        page.update(...)
        maxHeightInRow = max(maxHeightInRow, scaledPageHeight)
    currentY += maxHeightInRow

totalWidth = viewSize.width * vZoom
totalHeight = currentY
```

### 3.5 Page.update() 内部逻辑

```kotlin
fun update(width: Float, height: Float, rect: Rect) {
    this.width = width
    this.height = height
    this.bounds = rect           // Page在文档中的位置
    this.yOffset = bounds.top    // 垂直偏移（用于PageNode坐标转换）
    this.xOffset = bounds.left   // 水平偏移
    this.totalScale = width / aPage.width  // 整体缩放比例
    
    invalidateNodes()  // 重新计算TileConfig（分块配置）
}
```

### 4.2 updateVisiblePages() - 核心可见性算法

#### 4.2.1 多列模式

```kotlin
visibleRect = Rect(-offset.x, -offset.y, viewSize.width - offset.x, viewSize.height - offset.y)

pageToRender = pages.filter { page ->
    scaledBounds = scale(page.bounds)
    scaledBounds.overlaps(visibleRect)
}
```

#### 4.2.2 单列垂直模式 - 二分查找优化

```
visibleTop = -offset.y
visibleBottom = viewSize.height - offset.y
preloadBottom = visibleBottom + viewSize.height * preloadScreens  // 向下预加载一屏

// 二分查找可见范围
first = findVerticalFirstVisible(visibleTop, currentVZoom)
last = findVerticalLastVisible(preloadBottom, currentVZoom)

// 二分查找逻辑:
findVerticalFirstVisible(top):
    low=0, high=pages.size-1, result=pages.size
    while low <= high:
        mid = (low+high)/2
        if page.bounds.bottom * scaleRatio > top:
            result = mid, high = mid - 1
        else:
            low = mid + 1

pageToRender = pages.subList(first, last + 1)
```

#### 4.2.3 单列水平模式 - 二分查找优化

```
visibleLeft = -offset.x
visibleRight = viewSize.width - offset.x
preloadRight = visibleRight + viewSize.width * preloadScreens  // 向右预加载一屏

first = findHorizontalFirstVisible(visibleLeft, currentVZoom)
last = findHorizontalLastVisible(preloadRight, currentVZoom)
```

### 4.3 页面可见性变化处理

```kotlin
// 1. 计算新旧页面key集合的差集
newPageKeys = pageToRender.map { it.aPage.index }.toSet()
toRemove = lastPageKeys - newPageKeys

// 2. 清理不再可见的页面的所有Node

    pages.getOrNull(key)?.clearVisibleNodes()  // 回收所有PageNode到对象池

// 3. 更新每个可见页面的Node

    page.updateVisibleNodes(visLeft, visTop, visRight, visBottom, scaleRatio)

// 4. 更新列表

    pageToRender = tilesToRenderCopy  // Compose响应式更新，触发重组重绘
```

## 5. Page.updateVisibleNodes - 瓦片管理

### 5.1 TileConfig 计算

```kotlin
// 单轴分块策略:
const MIN_BLOCK = 256f   // 最小块大小
const MAX_BLOCK = 512f   // 最大块大小

calcAxisBlocks(length: Float): Int {
    if (length <= MAX_BLOCK) return 1          // ≤512px 不分块
    blocks = ceil(length / MAX_BLOCK)           // 按512分块
    if (actualBlockSize < MIN_BLOCK)            // 兜底: 如果实际块<256,按256重新分
        blocks = ceil(length / MIN_BLOCK)
    return blocks
}
```

### 5.2 可见Node按需创建

```kotlin
fun updateVisibleNodes(visLeft, visTop, visRight, visBottom, scaleRatio) {
    // 计算Page在屏幕上的位置
    cbLeft = bounds.left * scaleRatio
    cbTop = bounds.top * scaleRatio
    
    // 计算可见区域在Page相对坐标[0,1]中的范围
    pageVisibleLeft = (visLeft - cbLeft) / currentWidth
    pageVisibleRight = (visRight - cbLeft) / currentWidth
    pageVisibleTop = (visTop - cbTop) / currentHeight
    pageVisibleBottom = (visBottom - cbTop) / currentHeight
    
    // 计算需要哪些Block
    minBlockX = floor(pageVisibleLeft * config.xBlocks)
    maxBlockX = ceil(pageVisibleRight * config.xBlocks)
    minBlockY = floor(pageVisibleTop * config.yBlocks)
    maxBlockY = ceil(pageVisibleBottom * config.yBlocks)
    
    // 按需创建Node（使用对象池）
    for (y in minBlockY..maxBlockY)
        for (x in minBlockX..maxBlockX)
            key = (x shl 16) or y  // Int编码代替Pair
            if (!visibleNodes.containsKey(key))
                rect = Rect(x/xBlockCount, y/yBlockCount, (x+1)/xBlockCount, (y+1)/yBlockCount)
                node = nodePool.acquire(pageViewState, rect, aPage)
                visibleNodes[key] = node
    
    // 移除范围外的Node + 触发范围内Node的解码
    iterator:
        if key 在范围内 → entry.value.decode(currentWidth, currentHeight)  // 触发解码
        else → nodePool.release(entry.value), iterator.remove()            // 回收
}
```

### 5.3 单块模式优化

当 `TileConfig.isSingleBlock == true` (xBlocks=1, yBlocks=1) 时：
- 整个页面作为一个Node，不进行分块
- 直接创建单一Node(0,0)并解码
- 适用于缩放级别较低或页面尺寸较小的情况

### 6.2 Page.draw()

```kotlin
fun draw(drawScope, offset, vZoom) {
    // 1. 计算缩放后的实际尺寸和位置
    scaleRatio = vZoom / pageViewState.vZoom
    currentBounds = bounds * scaleRatio
    
    // 2. 快速可见性判断（O(1)）
    if (!isActuallyVisible && !isPageInVisibleList) return
    
    // 3. 尝试获取/加载缩略图（保证快速显示）
    if (thumbBitmapState == null) loadThumbnail()
    
    // 4. 如果可见，绘制缩略图（立即显示低分辨率内容）
    if (isActuallyVisible && thumbBitmapState != null) {
        drawImage(bitmap, currentBounds.left, currentBounds.top, currentWidth, currentHeight)
        loadLinks()  // 懒加载链接数据
    }
    
    // 5. 绘制高清瓦片（PageNode）
    drawNodes(drawScope, currentWidth, currentHeight, currentBounds)
    
    // 6. 绘制覆盖层（仅可见时）
    if (isActuallyVisible && thumbBitmapState != null) {
        drawLinks()                 // 链接区域高亮
        drawTextSelection()         // 文本选择高亮
        drawSearchHighlight()       // 搜索高亮
        drawSpeakingIndicator()     // 朗读指示边框
        drawAnnotation()            // 手写注释
        drawSeparator()             // 页面分割线
    }
}
```

### 6.3 PageNode.draw()

```kotlin
fun draw(drawScope, pageWidth, pageHeight, xOffset, yOffset) {
    // 1. 计算像素矩形（带缓存）
    pixelRect = getCachedPixelRect(pageWidth, pageHeight, xOffset, yOffset)
    
    // 2. 预加载可见性检查，完全超出预加载区域→回收
    if (!isTileVisible(pixelRect, strictMode=false)) {
        recycle(); return
    }
    
    // 3. 严格可见性检查
    isStrictlyVisible = isTileVisible(pixelRect, strictMode=true)
    
    // 4. 严格可见才绘制位图
    if (isStrictlyVisible && bitmapState != null && !recycled) {
        drawImage(bitmap, dstOffset, dstSize)
    }
    
    // 5. 解码在外部触发（decode()方法独立调用）
}
```

## 7. 解码流程

### 7.1 缩略图解码 (Page.loadThumbnail)

```
触发时机:
  - Page.draw() 中检测到 thumbBitmapState == null
  - 或者第一次进入可见区域

流程:
  1. 计算cacheKey: "thumb-{pageIndex}-{width}x{height}-{cropEnabled}"
  2. 检查ImageCache.acquirePage(cacheKey)  // 缓存命中直接使用
  3. 未命中 → 创建DecodeTask(type=PAGE):
     - 使用calculateThumbnailSize()计算输出尺寸（根据原图大小动态调整）
     - 提交到DecodeService
  4. 解码完成回调:
     - ImageCache.putPage(cacheKey, bitmap)
     - 主线程更新thumbBitmapState
     - notifyDecodeCompleted()触发Compose重组
```

### 7.2 瓦片解码 (PageNode.decode)

```
触发时机:
  - Page.updateVisibleNodes() 中调用 node.decode(currentWidth, currentHeight)

流程:
  1. 快速失败检查:
     - activeDecodeKey == currentKey → 已提交相同任务，跳过
     - isDecoding → 正在解码中，跳过
     - bitmapState != null && !recycled → 已有有效位图，跳过
  2. 检查ImageCache.acquireNode(cacheKey)  // 缓存命中直接使用
  3. 未命中 → 创建DecodeTask(type=NODE):
     - 计算srcRect（在原始PDF坐标中的区域）
     - 计算outWidth/outHeight（输出像素尺寸）
     - 安全保护: outWidth > MAX_BLOCK*2 或 outHeight > MAX_BLOCK*2 时跳过
     - 提交到DecodeService
  4. 解码完成回调:
     - ImageCache.putNode(cacheKey, bitmap)
     - 回收旧的bitmapState
     - 再次检查可见性后才设置新的bitmapState
     - notifyDecodeCompleted()触发Compose重组
```

### 7.3 DecodeService 调度机制

```
三队列优先级: PAGE(缩略图) > NODE(瓦片) > CROP(裁剪检测)

调度逻辑:
  1. 单消费者协程轮询 selectNextTask()
  2. 按优先级顺序检查三个 ConcurrentLinkedQueue
  3. 执行任务前检查:
     - shouldRender() 回调 → 不可见则跳过
     - ImageCache.hasTask() 去重
  4. 执行后:
     - 从 pendingJobs 移除
     - 调用回调的 onDecodeComplete / onFinish
```

### 7.4 shouldRender() 回调（用于取消不可见的解码）

```kotlin
// PageNode

    if (!isPageInVisibleList(pageNumber)) return false  // O(1)检查
    return isTileVisible(tileSpec, strictMode=false)     // 预加载区域内

// Page (缩略图)
```

### 8.2 手势处理流程 (VIEW模式)

```

    event = awaitPointerEvent()
    
    if zooming (多指):
        centroid = event.calculateCentroid()
        zoomChange = event.calculateZoom()

    else (单指拖动):

        offset = calculateBounds(offset, ...)

    consume changes
    
while any pointer pressed

// 手势结束后:
if 非缩放模式 && 拖动距离 < 10px:
    handleTapGestureInternal()  // 点击处理（翻页/双击检测）
```

### 8.4 边界计算 (calculateBounds)

```kotlin
fun calculateBounds(targetOffset, currentZoom, size, pageViewState, ori): Offset {
    scaleRatio = currentZoom / pageViewState.vZoom
    
    contentWidth  = if vertical → size.width * currentZoom
                    else → pageViewState.totalWidth * scaleRatio
    
    contentHeight = if vertical → pageViewState.totalHeight * scaleRatio
                    else → size.height * currentZoom
    
    minX = if (contentWidth > size.width) size.width - contentWidth else 0f
    minY = if (contentHeight > size.height) size.height - contentHeight else 0f
    
    return Offset(targetOffset.x.coerceIn(minX, 0f), targetOffset.y.coerceIn(minY, 0f))
}
```

### 8.5 惯性滚动 (performFling)

```kotlin
fun performFling(velocity, ...) {
    decay = exponentialDecay(frictionMultiplier=0.35f, absVelocityThreshold=0.50f)
    velocity *= 1.1f
    
    scope.launch {
        animatable.animateDecay(velocity, decay) {
            offset = calculateBounds(value, vZoom, ...)
            pageViewState.updateOffset(offset)  // 动画过程中持续更新可见页面
        }
    }
}
```

## 9. 内存管理与缓存

### 9.1 缓存层级

```
第一层: ImageCache (LRU内存缓存)
  ├── nodeCache: 256MB, 存储PageNode解码后的位图
  └── pageCache: 32MB, 存储Page缩略图位图
  
第二层: CandidatePool (二次存活机会，60秒)
  从LRU中被淘汰的位图，放入候选池保留60秒
  如果在60秒内被重新访问，回到主缓存
  超过60秒，允许GC回收

引用计数: BitmapState (AtomicInteger)
  低31位: 引用计数
  第32位: 已回收标记
  acquire() +1, release() -1
  引用计数归零且超过60秒 → 可以被回收
```

### 9.2 对象池 (PageNodePool)

```
大小限制: 最多缓存32个PageNode对象
作用: 避免缩放/滚动时频繁创建和销毁PageNode（高缩放级别约12-16个节点）

acquire():
    if 池不为空: 从队首取一个，调用node.recycle() + node.update()
    else: 新建PageNode

release(node):
    node.recycle()  // 回收位图、取消Job
    if 池未满: 放回队尾
    else: 丢弃（让GC回收）
```

### 9.3 主动清理策略

```
清理时机:
  1. updateVisiblePages() 中:
     - 计算新旧key差集
     - 对不再可见的Page → page.clearVisibleNodes() → 回收所有PageNode
     
  2. PageNode.draw() 中:
     - 超出预加载区域 → node.recycle()
     
  3. PageViewState.shutdown() 中:
     - 回收所有Page，清空pageToRender
     - 关闭DecodeService
     - 清空nodePool
     - 调用System.gc()
     
  4. 切边变化、列数变化时:
     - 回收所有Page的缩略图缓存
     - ImageCache.clearNodes() 或 clear()
```

## 10. 完整生命周期

### 10.1 一次完整的滚动流程

```
用户手指拖动
    ↓
CommonGestureHandler → offset += panChange
    → calculateBounds() 限制边界
    → pageViewState.updateOffset(offset)
        ↓
        updateVisiblePages(newOffset, viewSize, vZoom)
            ↓
            二分查找可见页面范围（垂直/水平）
            ↓
            计算新集合与旧集合的差集
            ↓
            清理不再可见的Page的Nodes → nodePool.release()
            ↓
            更新pageToRender列表 → Compose重组
            ↓
            对每个可见Page调用updateVisibleNodes()
                ↓
                计算可见区域的Block范围
                ↓
                从对象池acquire新的PageNode（按需）
                ↓
                移除范围外的PageNode → nodePool.release()
                ↓
                对范围内的PageNode调用decode()
                    ↓
                    检查缓存 → 命中直接返回
                    未命中 → 提交DecodeTask到DecodeService
                        ↓
                        DecodeService调度 → DecoderAdapter解码
                        → ImageBitmap返回
                        → ImageCache缓存
                        → bitmapState更新
                        → Compose重组渲染
        ↓
        DocumentViewCanvas重新绘制
            ↓
            pageViewState.drawVisiblePages()
                ↓
                Page.draw() 每个可见页面
                    ↓
                    如果有缩略图 → 先绘制低分辨率版本
                    ↓
                    drawNodes() → PageNode.draw() 每个瓦片
                        ↓
                        可见性再次检查
                        ↓
                        有bitmap → DrawScope.drawImage()
```

### 10.2 缩放流程

```
双指缩放
    ↓
CommonGestureHandler → calculateZoom()
    → newZoom = (vZoom * zoomChange).coerceIn(1f, max_zoom)
    → 计算缩放中心:
        centerOffsetX = (viewSize.width - totalWidth) / 2  // 内容小于视图时的居中偏移
        contentCenterX = centroid.x - offset.x - centerOffsetX
        newOffsetX = centroid.x - contentCenterX * zoomFactor - centerOffsetX
    → vZoom = newZoom
    → offset = calculateBounds(newOffset, ...)
    ↓
手势结束:
    pageViewState.updateOffset(offset)
    pageViewState.updateViewSize(viewSize, vZoom, orientation)
        → invalidatePageSizes()  // viewSize不变但vZoom变，重新计算布局
        → updateVisiblePages()   // 重新计算可见页面
```

### 10.3 页面跳转流程

```
外部请求跳转到第N页:
    ↓
PageViewState.onPageLinkClick 或 jumpToPage LaunchedEffect
    ↓
if PageRestore模式:
    尝试用保存的scrollX/scrollY恢复
    如果第一页与目标页不符 → 用页面bounds.top/left跳转
    
if PageNavigation模式:
    水平模式: offset.x = -(page.bounds.left)
    垂直模式: offset.y = -(page.bounds.top)
    支持jumpOffsetY精确偏移
    ↓
offset更新 → updateOffset() → 后续同滚动流程
```

## 11. 关键设计决策

### 11.1 Canvas绘制 vs LazyColumn

选择Canvas而非LazyColumn的原因：
1. 需要精细控制缩放（双指缩放时所有元素一起缩放）
2. 需要叠加绘制链接、注释、高亮等多种覆盖层
3. 需要高性能瓦片渲染（Canvas直接操作位图绘制）
4. Canvas配合 graphicsLayer 实现硬件加速的偏移和缩放

### 11.2 二分查找 vs 遍历

对于垂直/水平滚动，可见页面查找使用二分查找（O(log n)），而非遍历（O(n)）：
- 所有页面的bounds在布局计算后是有序的（垂直按Y排序，水平按X排序）
- 缩放比例影响bounds，但相对顺序不变
- findVerticalFirstVisible/findVerticalLastVisible 使用经典二分搜索

### 11.3 缩略图 + 瓦片双重渲染

```
优势:
  1. 缩略图（低分辨率）可以极快地解码和显示
  2. 用户立即看到内容，无需等待高清瓦片
  3. 瓦片逐步替换缩略图，体验平滑
  4. 缩略图缓存32MB，瓦片缓存256MB，分层管理

缺陷:
  1. 两层渲染增加复杂性
  2. 内存占用比纯瓦片方案高
```

### 11.4 多列布局

多列布局使用不同的布局算法：
- 行内取最高页作为行高
- 可见性判断使用Rect.overlaps（非二分查找，因为布局非严格垂直有序）
- 预加载策略同单列

## 12. 关键优化点

| 优化 | 位置 | 效果 |
|------|------|------|
| 二分查找可见页面 | PageViewState.updateVisiblePages | O(log n) 替代 O(n) |
| PageNode对象池 | PageNodePool | 避免高频GC |
| 像素矩形缓存 | PageNode.getCachedPixelRect | 避免重复计算 |
| Int编码替代Pair | Page.visibleNodes key = (x shl 16) or y | 零分配 |
| 内联可见性检查 | isVisibleInline (直接传坐标) | 避免Rect对象创建 |
| LRU + 候选池 | ImageCache | 缓存命中率高，二次存活 |
| shouldRender回调 | DecodeCallback | 避免不可见页面的无效解码 |
| 延迟链接加载 | Page.loadLinks | 按需加载 |
| 缩略图优先 | Page.draw thumbBitmapState | 快速首屏显示 |
| Compose mutableStateOf | 各状态字段 | 精准重组，避免全量刷新 |
